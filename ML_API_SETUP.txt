# DETECT-CO ML API: local network discovery

The backend advertises `_detectco-ml._tcp.local` while FastAPI is running.
The Flutter app discovers the service, uses its resolved IPv4 address, and
checks `/health` before sending the existing `/predict` request. It caches the
healthy endpoint, invalidates it when connectivity changes, and retries the
normal five-minute prediction flow. A manual address is available in Menu >
Display Settings > ML Server Address.

## Install and start the API

```bash
cd ~/DETECT-CO/DETECT-CO-ML
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn api:app --host 0.0.0.0 --port 8000
```

The server binds to all laptop interfaces for LAN access. The mDNS advertiser
tracks local IPv4 changes while the process runs and unregisters when Uvicorn
shuts down. If mDNS cannot start, FastAPI still runs and the manual address
setting remains available. The API continues to use the real LSTM, XGBoost,
Random Forest, and Open-Meteo prediction pipeline.

## Verify locally

In another terminal on the laptop:

```bash
curl -fsS http://127.0.0.1:8000/health
curl -fsS -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"latitude":14.15,"longitude":121.05}'
```

The prediction response should contain `predictions` with the five rainfall
fields for 1, 3, 6, 12, and 24 hours.

To check the DNS-SD advertisement on Linux, install `avahi-utils` and run:

```bash
avahi-browse --resolve --terminate _detectco-ml._tcp
```

## Flutter

```bash
cd ~/DETECT-CO
flutter pub get
flutter run
```

`ML_API_URL` remains available for local development and tests and takes
priority over discovery:

```bash
flutter run --dart-define=ML_API_URL=http://127.0.0.1:8000/predict
```

If Android mDNS is blocked by the Wi-Fi network or device, open Menu > Display
Settings > ML Server Address and enter `192.168.1.41:8000` (or the laptop's
current LAN address). Leave it empty or choose Auto Discover to return to
DNS-SD discovery. On Android emulators, use `10.0.2.2:8000` as the manual
address. Do not enter `0.0.0.0` or rely on `detectco-server.local` resolving.

## Firewall and network

Both devices must be on the same Wi-Fi/LAN, and the router must allow local
device-to-device traffic and multicast DNS. For Linux firewalls, allow inbound
TCP port 8000 only from the private Wi-Fi subnet and allow local UDP multicast
to `224.0.0.251:5353` on the Wi-Fi interface. For UFW, replace the example
subnet with the laptop's actual subnet:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8000 proto tcp
```

Do not create a public port-forward. Android debug builds permit HTTP for this
LAN development API; release traffic should use an HTTPS deployment. The main
Android manifest includes INTERNET permission, and Bonsoir supplies the
multicast permission and short-lived receive lock needed for discovery.

## Test a Wi-Fi change

Keep Uvicorn running, move the laptop and phone to another shared Wi-Fi
network, then wait for the network connection event and the laptop's mDNS
address refresh. The Flutter app discards its cached IP and rediscovers the
server. If that network blocks multicast, save the laptop's new IP in the
manual setting. If the devices are separated or the laptop is off, ML requests
fail with a connection message and the existing Open-Meteo fallback remains
active.
